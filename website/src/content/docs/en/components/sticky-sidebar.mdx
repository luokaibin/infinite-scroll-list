`<sticky-sidebar>` provides responsive sticky-sidebar behavior: when the viewport reaches the configured breakpoint, sticking is enabled and the component measures the sidebar content height — applying a negative `top` offset when the content is taller than the viewport so it can be fully scrolled into view; below the breakpoint the original styles are restored.

## Live demo

The sidebar content in the templates is taller than the preview viewport — notice the component has already set a negative `top` offset. The second template lets you switch breakpoints dynamically.

## Usage

```html
<div style="display: flex; gap: 20px">
  <div class="main"><!-- main content --></div>
  <sticky-sidebar min-width="1024">
    <div class="sidebar"><!-- sidebar content --></div>
  </sticky-sidebar>
</div>

<style>
  sticky-sidebar {
    position: sticky;
    top: 0;
    transition: top 0.3s ease-in-out;
  }
</style>
```

How it works:

1. `matchMedia` watches the viewport against the `min-width` breakpoint
2. Above the breakpoint it measures the sidebar content height: taller than the viewport sets `top = -(content - viewport)`; shorter restores the original `top`
3. Below the breakpoint the original styles are restored (sticking disabled)
4. `ResizeObserver` + debounced `window resize` + `requestAnimationFrame` keep it responsive and fast

## Attributes

| Attribute | Type | Default | Description |
| --- | --- | --- | --- |
| `min-width` | Number | `1024` | Minimum viewport width (px) for sticking; values are validated and clamped to `0 ~ 3840` |

## Methods

| Method | Params | Returns | Description |
| --- | --- | --- | --- |
| `getBreakpointStatus()` | — | `Status` | Current state: `breakpoint`, `currentWidth`, `isAboveBreakpoint`, `mediaQuery`, `isStickyActive` |
| `setBreakpoint(breakpoint)` | `string \| number` | `number` | Programmatically set the breakpoint (goes through the `min-width` attribute path; returns the validated value) |
| `forceRecalculation()` | — | `void` | Force a recalculation of the sticky behavior |

## Notes

- **No Shadow DOM**: the component only provides behavior and ships no internal styles — the sticking CSS (`position: sticky; top: 0;`) is fully provided by the host app
- A content height of 0 or invalid values never applies an offset; breakpoint values outside `0 ~ 3840` are clamped with a warning
- Migration note: the source package's debug `console.log` statements were stripped during migration; `warn` / `error` diagnostics are kept
- SSR-safe: importing the entry is a no-op on the server — see [Loading Timing & SSR](../../guides/ssr-and-timing/)
- Browser support: all modern browsers (Chrome / Firefox / Safari / Edge)
